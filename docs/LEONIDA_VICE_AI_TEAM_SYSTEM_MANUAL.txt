2. HARDWARE & INFERENCE PARADIGM: WHY GROQ LPUs?
====================================================================================================
Most generative AI applications suffer from latency bottlenecks when deployed in production. 
Traditional graphics processing units (GPUs like Nvidia H100, A100, or RTX 4090) utilize Single 
Instruction Multiple Threads (SIMT) architectures bound by external High-Bandwidth Memory (HBM).

2.1 TSP vs GPU Architecture (SRAM vs HBM)
----------------------------------------------------------------------------------------------------
Groq utilizes a proprietary Tensor Streaming Processor (TSP) architecture known as the Language 
Processing Unit (LPU). Instead of moving model weights across external memory buses, the entire 
model execution graph is compiled statically into high-bandwidth on-chip SRAM (Static RAM).
  - Memory Bandwidth: Groq LPUs achieve up to 80 terabytes per second of on-chip memory bandwidth.
  - Predictable Instruction Timing: Execution has zero dynamic instruction scheduling or cache 
    miss penalties. Every clock cycle is mathematically planned during model compilation.

2.2 Deterministic Execution & Sub-Second Latency (~500 Tokens/Sec)
----------------------------------------------------------------------------------------------------
In benchmark runs on Leonida Vice:
  - Short-form news flashes (Lexi Wire on openai/gpt-oss-20b):
    Average generation time: 0.27 to 0.45 seconds (~500-650 tokens/sec).
  - Long-form deep investigative drafts (Vincent Vance on openai/gpt-oss-120b):
    Average generation time: 1.69 to 3.80 seconds for 800-1400 tokens (~400-500 tokens/sec).
This deterministic speed transforms AI from an asynchronous background wait into an instantaneous, 
conversational tool suitable for real-time editorial newsrooms.

2.3 Groq Prompt Caching (50% Cost Reduction via Static Brand Prefixes)
----------------------------------------------------------------------------------------------------
Groq features automatic server-side prompt caching. When the system detects an identical prefix of 
1,024 tokens or more between requests:
  - Cache Hit Price: 50% discount on input tokens.
  - Ingestion Latency: Prompt processing latency drops to near-zero milliseconds.
To maximize this, all Leonida Vice system prompts share a standardized static brand prefix:
"You are the Senior Managing Editor for NewVice Media (Leonida Vice), a premier digital investigative..."

4. SYSTEM 1: MULTI-MODEL AUTOMATED ARTICLE GENERATION ENGINE (groq_article_engine.py)
====================================================================================================
The article generation engine is a standalone Python CLI and library located at:
leonida-vice/scripts/groq_article_engine.py

4.1 Canonical Fact Base & Anti-Hallucination Retrieval (canonical_facts.json)
----------------------------------------------------------------------------------------------------
To prevent large language models from hallucinating non-existent GTA VI mechanics or misnaming 
characters, the engine references an authoritative local JSON index:
leonida-vice/scripts/canonical_facts.json

Key canonical facts indexed:
  - Characters: Lucia Caminos (first female HD-era protagonist, former inmate at Leonida State 
    Penitentiary), Jason Duval (combat veteran and partner in crime), Raul Bautista (cartel broker).
  - Locations: Vice City (Ocean Beach, Washington Beach, Little Haiti, Starfish Island), Leonida Keys 
    (Overseas Highway US-1), Mount Kalaga National Park (pine wilderness), Port Gellhorn (industrial 
    port/refineries), Ambrosia (sugar cane rural hub).
  - Technology: Rockstar Advanced Game Engine (RAGE 9), water displacement, ray-traced lighting.
  - Launch Window: Fall 2026 (November 19, 2026).

During execution, relevant categories are extracted (<500 tokens) and injected directly into the 
user prompt, ensuring 100% lore compliance.

4.2 Strict Mode JSON Schemas (strict: true)
----------------------------------------------------------------------------------------------------
The Groq API supports OpenAI-compatible Structured Outputs. By specifying `"strict": true` in the 
`response_format` configuration, the model is physically constrained at the decoding stage by 
a context-free grammar compiler.

The schema definition enforces:
  - headline: string, strictly <= 60 characters.
  - slug: kebab-case URL identifier.
  - meta_description: string, 120-155 characters.
  - category: enum of allowed website categories:
    ["Story & Campaign", "Map & Locations", "Vehicles & Weapons", "Online & Features",
     "Trailers & Media", "Leaks & Rumors", "Guides & Walkthroughs", "Tech & Rage"]
  - takeaway_bullets: array of strings (minimum 3 items).
  - body_markdown: rich markdown text containing ## headers, paragraphs, and pull-quotes.
  - tags: array of strings for taxonomy indexing.
  - target_keywords_included: array of confirmed SEO keywords.

4.3 Reasoning Token Headroom Management
----------------------------------------------------------------------------------------------------
Modern reasoning models (such as openai/gpt-oss-120b and openai/gpt-oss-20b) generate internal 
"thought" or reasoning tokens prior to emitting the final schema payload.
  - Issue: If `max_completion_tokens` is configured too low (e.g. 2,000 tokens), the model's 
    internal reasoning consumes the quota, resulting in `json_validate_failed` or truncated output.
  - Solution: In `groq_article_engine.py` and `/api/admin/ai-team/route.ts`, token limits are 
    explicitly set to `max_completion_tokens: 6144` or `8192`, with `temperature: 0.3` to 
    ensure rock-solid schema completion.

4.4 Multi-Model Cascading Fallback (120B -> 20B)
----------------------------------------------------------------------------------------------------
If the 120B model encounters a rate limit (HTTP 429), unexpected timeout, or temporary server 
congestion, the system automatically catches the error and cascades to the ultra-fast 20B model:
```python
try:
    completion = client.chat.completions.create(model="openai/gpt-oss-120b", ...)
except Exception as e:
    print("120B congested, cascading to 20B fallback...")
    completion = client.chat.completions.create(model="openai/gpt-oss-20b", ...)
```

4.5 Deterministic Post-Processing Pipeline
----------------------------------------------------------------------------------------------------
After receiving the payload from the LPU, deterministic code verifies:
  1. Headline Length: If > 60 chars, it is automatically truncated at the last word boundary.
  2. Slug Sanitization: Converted to lowercase alphanumeric kebab-case with special characters removed.
  3. Keyword Saturation: Verifies whether all requested keywords exist in the body. If missing, 
     they are naturally appended into an editorial footnote.
  4. Output Storage: Articles are saved as JSON files in `scripts/output/` and can be pushed 
     directly into `data/newspaper-store.json` or Supabase.

5. SYSTEM 2: PLAYWRIGHT SITE RELIABILITY & QA WATCHDOG (newvice_watchdog.py)
====================================================================================================
Located at: leonida-vice/scripts/newvice_watchdog.py
The watchdog operates as an automated testing and quality assurance daemon for the live website.

5.1 Chromium Headless Automation & Autoplay Policy Configuration
----------------------------------------------------------------------------------------------------
Using Playwright v1.64.1+, the watchdog launches an isolated Chromium browser instance configured 
with the flag:
`--autoplay-policy=no-user-gesture-required`
This allows the test runner to evaluate the live broadcast player in a true headless environment 
without requiring simulated user mouse clicks.

5.2 HTML5 Video Decoder Health State Machine
----------------------------------------------------------------------------------------------------
The watchdog probes the `<video>` element on the homepage (`/`) and player routes (`/room/*`):
  - readyState >= 3 (HAVE_FUTURE_DATA) or 4 (HAVE_ENOUGH_DATA): Confirms chunks are buffered.
  - paused === false: Confirms video stream has started.
  - ended === false: Confirms clip has not prematurely halted.
  - error === null: Confirms no decode or codec failure.

5.3 Temporal Playhead Advancement Test
----------------------------------------------------------------------------------------------------
Static properties can produce false positives if a video is frozen on frame 0. To guarantee active 
decoding, the watchdog executes a temporal delta test:
  1. Records initial playhead position: `t0 = video.currentTime`.
  2. Sleeps asynchronously for 2,500 milliseconds.
  3. Records second playhead position: `t1 = video.currentTime`.
  4. Asserts: `t1 > t0 + 1.5`. If true, video frames are actively rendering.

5.4 Broadcast Queue Rotation & Carousel Sync
----------------------------------------------------------------------------------------------------
The script validates the live playlist carousel:
  - Inspects active clip index in the DOM.
  - Clicks next track button (`[data-action="next-clip"]` or keyboard shortcut).
  - Asserts that active clip index updates, title transitions smoothly, and new video src loads.

5.5 Asynchronous Link & Image 404 Integrity Audit
----------------------------------------------------------------------------------------------------
Using `httpx.AsyncClient`, the watchdog extracts all `<img>` src attributes and `<a href>` links 
from the rendered DOM:
  - Sends asynchronous `HEAD` and `GET` requests with concurrent workers.
  - Flags any 404 Not Found, 500 Server Error, or broken image URLs.
  - Reports zero broken images across all 48 canonical broadsheet articles.

5.6 Token-Distilled DOM Extraction & LLM Consistency Proofreader
----------------------------------------------------------------------------------------------------
Rather than passing 50,000 characters of raw HTML to an LLM, the watchdog strips script tags, SVG 
paths, and style sheets to create a distilled DOM text excerpt (<1,500 tokens).
This excerpt is submitted to Sentinel-9 on Groq:
  - Prompt: "Identify any lorem ipsum text, broken formatting brackets, grammatical mistakes, or 
    lore discrepancies contradicting Grand Theft Auto VI canon."
  - The model outputs a JSON assessment: `{"passed": true/false, "flags": [...]}`.

5.7 SQLite Audit Persistence (newvice_watchdog_audit.db) & Alert Hooks
----------------------------------------------------------------------------------------------------
Every check result is written to an SQLite database: `scripts/newvice_watchdog_audit.db`.
Schema:
  - id: INTEGER PRIMARY KEY
  - timestamp: ISO 8601 UTC
  - page_url: string
  - check_type: string ("video_decoder", "queue_rotation", "404_audit", "llm_proofread")
  - passed: boolean (1 or 0)
  - detail: string description of outcome

If a critical failure occurs, an optional webhook alerts the newsroom via Slack or Discord.

7. SECURITY, CREDENTIALS & VERCEL SERVERLESS ROUTING
====================================================================================================

7.1 GitHub Push Protection & Secret Scanning Architecture
----------------------------------------------------------------------------------------------------
The Git repository for Leonida Vice is hosted publicly at:
https://github.com/agayle8671-cmyk/newvice.git

GitHub enforces automated push protection. If an API key matching patterns like `gsk_*` (or even 
its raw base64 string) is included in any commit, the `git push` is blocked at the remote layer. 
This is a vital safeguard that prevents token leakage and billing abuse.

7.2 Local Storage Security Model (lv_groq_api_key)
----------------------------------------------------------------------------------------------------
To keep credentials secure while delivering a frictionless web interface:
  1. The API key is stored strictly on the client side in browser `localStorage.getItem("lv_groq_api_key")`.
  2. The key is never committed to GitHub or exposed in public client bundles.
  3. When an admin user enters the key in the UI, it persists in their local browser.
  4. For every AI request, the client transmits the key over secure HTTPS via the `x-groq-api-key` header.

7.3 HTTPS Header Transmission & Passcode Gateway
----------------------------------------------------------------------------------------------------
In `/api/admin/ai-team/route.ts`:
  1. Verification: The route verifies the admin session via `verifyAdminRequest(request)` using 
     either the HTTP-only cookie or the `x-admin-passcode: leonida305` header. Unauthorized calls 
     receive HTTP 401.
  2. Key Resolution Hierarchy:
     `const groqApiKey = process.env.GROQ_API_KEY || request.headers.get("x-groq-api-key") || body.groqApiKey;`
  3. Error Handling: If no key is provided, the API returns HTTP 400 with a clear prompt directing 
     the user to click the `⚙️ Key` button.

9. IDENTIFIED SYSTEM BOTTLENECK AUDIT
====================================================================================================
While the current architecture is fast and operational, an audit identifies the following areas 
for enhancement:

1. Static Fact Base Size:
   `canonical_facts.json` currently holds ~18 core lore facts. As GTA VI information expands, 
   stuffing the entire index into the prompt prefix will exceed token budgets and inflate latency.
2. Unidirectional Communication:
   Agents operate independently. Chief Vance does not automatically critique or review drafts 
   written by Lexi Wire before they reach the operator.
3. Manual Publishing Trigger:
   The user must manually click "Load Into Composer" and "Publish". There is no scheduled cron job 
   that autonomously aggregates sources, writes an article, and pushes it to Supabase drafts.
4. Watchdog Passive Logging:
   When Sentinel-9 detects a broken link or image, it writes the result to SQLite or Slack, but does 
   not autonomously self-heal by substituting a working backup asset.
5. Text-Only Generation:
   The engine generates headline, excerpt, and body text, but relies on existing image libraries 
   rather than dynamically synthesizing novel concept art or forensic diagrams.

10. COMPREHENSIVE ROADMAP FOR IMPROVEMENT & UPGRADE VECTORS
====================================================================================================
To elevate the Leonida Vice AI team from an assisted assistant setup to an autonomous enterprise 
newsroom, implement the following roadmap:

----------------------------------------------------------------------------------------------------
10.1 Vector RAG Integration (pgvector in Supabase / Qdrant)
----------------------------------------------------------------------------------------------------
  - Problem: `canonical_facts.json` cannot scale to hundreds of pages of leak analysis, trailer 
    breakdowns, and county maps.
  - Solution: Ingest all research PDFs (`GTA 6 Video Sources Research.pdf`, `Building GTA 6 Video 
    Crawler.pdf`, etc.) into a Supabase vector table using `pgvector` or an embedded vector store.
  - Implementation:
    When a user asks Chief Vance about "Port Gellhorn container yards", the system performs cosine 
    similarity search over vector chunks, retrieving only the 3 most relevant paragraphs (<300 tokens) 
    and feeding them as context.

----------------------------------------------------------------------------------------------------
10.2 Autonomous Multi-Agent Editorial Review Board (Debate & Refine Loops)
----------------------------------------------------------------------------------------------------
  - Pipeline Design:
    1. Lexi Wire (20B) receives a breaking leak and generates a rapid draft in 0.5s.
    2. Sgt. Cruz (Safeguard 20B) inspects the draft for offensive content or unverified personal data.
    3. Vincent Vance (120B) acts as Senior Editor, reading the draft, improving vocabulary, adding 
       historical lore references, and polishing the prose.
    4. Sentinel-9 verifies that all generated image tags and category slugs exist in the database.
  - Result: Production-ready investigative journalism without requiring operator proofreading.

----------------------------------------------------------------------------------------------------
10.3 Automated Scheduled Cron Publishing Pipeline
----------------------------------------------------------------------------------------------------
  - Mechanism: Utilize Vercel Cron Jobs (`vercel.json`) or a background Python scheduler.
  - Workflow:
    * Every 6 hours, a cron endpoint (`/api/cron/auto-editorial`) runs.
    * Queries the latest scraped video transcripts and community submissions.
    * Calls `groq_article_engine.py` to draft a "Daily Leonida Crime & Police Blotter".
    * Directly inserts the article into Supabase with `status: 'draft'` (or `status: 'published'`).
    * Sends a push notification or Discord ping: "New draft prepared by Chief Vance awaiting review."

----------------------------------------------------------------------------------------------------
10.4 Autonomous Self-Healing Infrastructure
----------------------------------------------------------------------------------------------------
  - Watchdog Enhancement:
    * When Sentinel-9 detects an image URL returning HTTP 404, the watchdog queries the local 
      media library for the closest semantic match (e.g., replaces a missing `grassrivers_02.jpg` 
      with verified `grassrivers_01.jpg`).
    * Updates `data/newspaper-store.json` and patches the database row automatically.
    * Commits the incident to the audit trail as: "AUTO-HEALED: Broken hero image replaced."

----------------------------------------------------------------------------------------------------
10.5 Generative Media Asset Generation (Image & Audio Podcasting)
----------------------------------------------------------------------------------------------------
  - Hero Image Generation:
    * Connect the Groq pipeline to a generative image API (e.g. FLUX.1 or Stable Diffusion).
    * Chief Vance crafts a photorealistic prompt based on the article's tone.
    * Automatically saves the resulting 16:9 banner into `/public/images/uploads/` and links it 
      as the article's `heroImage`.
  - Audio Radio Dispatch ("Leonida Vice Public Radio"):
    * Feed Lexi Wire's breaking news bullet points into a fast Text-to-Speech (TTS) model 
      (e.g., ElevenLabs or Whisper/Bark).
    * Generate a 30-second audio broadcast clip with retro police radio sound effects.
    * Play the audio dispatch over the live broadcast player during news flashes.

----------------------------------------------------------------------------------------------------
10.6 Streaming WebSocket War Room Chat
----------------------------------------------------------------------------------------------------
  - Current Behavior: The web chat waits for the entire completion to finish before rendering (1.6s).
  - Improvement: Implement Server-Sent Events (SSE) or WebSockets on `/api/admin/ai-team/route.ts` 
    to stream tokens onto the screen word-by-word at 500 tokens/second, creating a hyper-responsive
